# Sand Bucket

Личная браузерная игра по мотивам основной механики Sand Loop: цветной песок, вёдра на конвейере и один собственный уровень. Без рекламы, магазина, аккаунтов и сервера.

## Запуск

Node.js 22.12+ (CI использует Node.js 24), npm.

```sh
npm ci
npm run dev
```

Открыть адрес `/sand-bucket/`, который напечатает Vite. Для проверки production-сборки:

```sh
npm run check
npm run build
npm run preview
```

Dev-сервер доступен в локальной сети для проверки с телефона. Service Worker работает только в production-сборке на HTTPS или localhost; обычный HTTP по IP компьютера не проверяет офлайн-режим.

## Правила

- На поле 4 × 4 видны все 16 вёдер. Выбирать можно только ведро с проходом к верхнему краю через пустые клетки. Проход может поворачивать вверх, вниз, влево и вправо; диагонали не считаются.
- Доступные вёдра стоят нормально и крупнее остальных. Заблокированные перевёрнуты и уменьшены. Удалённое ведро оставляет пустую клетку, остальные не сдвигаются.
- На ленте пять движущихся углублений под вёдра. Выбранное ведро сразу занимает первый свободный слот; ждать освобождения входа не нужно.
- Лента идёт вправо и возвращается слева. Базовый оборот — 6 секунд. Кнопка ×1 / ×2 под лентой ускоряет всю симуляцию; правила сбора и осыпания не меняются.
- Ведро собирает свой цвет из пяти нижних рядов под собой, в том числе через другой цвет. Чужой песок остаётся на месте. Вместимость — точное количество песчинок.
- Полное ведро исчезает, освобождая слот. Неполное продолжает движение.
- Победа — собран весь песок. Проигрыш — невозможно добавить ведро и полный оборот ленты прошёл без сбора или осыпания. Само заполнение ленты не означает поражение.
- При смене вкладки игра становится на паузу. Перезапуск и новый заход сохраняют ту же раскладку и сбрасывают скорость на ×1. Сохраняется только отметка прохождения.

## Устройство

TypeScript + Vite + PixiJS (WebGL). Сетка 128 × 112, фиксированный шаг 60 Гц; песок рисуется одной текстурой. В режиме ×2 выполняется вдвое больше тех же шагов. Области нажатия в поле не меньше 44 × 44 CSS-пикселей, кнопки поддерживают клавиатуру и описания для скринридера.

- `src/game.ts`: состояние, доступность вёдер, слоты, симуляция и правила.
- `src/renderer.ts`: текстура песка, обрезаемые на краях фрагменты слотов, вёдра и потоки.
- `src/main.ts`: поле, меню, ускорение, пауза и локальное сохранение.

## Генерация решаемой раскладки

Генерация работает при разработке, не в браузере. Сохранённый уровень находится в `src/levels/shore.json`: seed, расположение и вместимость вёдер, точный проверочный маршрут и шаг победы. Песочная картинка остаётся «Тихим берегом».

```sh
npm run generate:level
# Или другой seed:
npm run generate:level -- 12345
npm run check
```

Команда меняет файл уровня только после успешной проверки. По умолчанию используется seed `20261029`.

1. Seed задаёт количество вёдер каждого цвета (2–6, всего 16), их вместимость и позиции. Сумма вместимостей точно равна количеству песка соответствующего цвета.
2. Генератор строит выигрышный маршрут без пространственных ограничений. Для этого он временно перемещает выбранное ведро на верхний край, затем запускает его обычным методом движка. Одновременно на ленте не больше одного ведра каждого цвета; это ограничение генератора, не игрока.
3. Вёдра размещаются на поле так, чтобы по маршруту каждый следующий выбор имел проход к ленте.
4. Маршрут повторно проигрывается с настоящим полем, пятью слотами и обычными правилами. Лимит — 30 000 шагов на прогон. Без победы генерация завершается ошибкой, непроверенный уровень не записывается.

CI воспроизводит сохранённый уровень, проверяет победу и ещё 20 фиксированных seed. Тесты также покрывают извилистые проходы, закрытые участки, запрет диагоналей, пять слотов, возврат с края, глубину сбора, вместимость, сохранение песка, тупики, чистый перезапуск и эквивалентность ×1/×2 при одинаковых действиях на шагах симуляции. Гарантия решаемости означает наличие выигрышного маршрута; неверный порядок ходов по-прежнему может привести к проигрышу.

## GitHub Pages и офлайн

Workflow проверяет типы, тесты и сборку. Только `main` публикуется в GitHub Pages; ветка разработки и PR проходят проверки без деплоя. Слияние требует отдельного одобрения владельца.

Адрес после публикации: https://lemonb.github.io/sand-bucket/ . База путей `/sand-bucket/` задана в `vite.config.ts`.

Service Worker заранее кеширует сборку и все локальные ресурсы. После сообщения «Можно играть без интернета» страницу можно открывать офлайн. На iPhone: Safari → Поделиться → На экран «Домой». Обновление применяется после закрытия всех окон игры и нового открытия; текущая партия не прерывается обновлением. Очистка данных браузера удалит кеш и локальную отметку прохождения.

## Проверка на устройстве перед релизом

- iPhone 13+: проверить плавность во время сбора пятью вёдрами, нагрев и управление пальцем. Цель — 60 кадров/с; desktop-проверка не подтверждает производительность телефона.
- Проверить безопасные отступы, всё поле 4 × 4, переключение ×2, возврат после блокировки экрана и сброс скорости при перезапуске.
- После первого полного открытия отключить интернет, закрыть игру и открыть снова с главного экрана.
- Пройти уровень, перезагрузить страницу и проверить сохранённую отметку.

Звук, генерация во время игры и дополнительные картинки уровней в эту версию не входят.

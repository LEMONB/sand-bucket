# Sand Bucket

Личная браузерная игра с кампанией из 400 проверенных уровней. TypeScript, Vite и PixiJS; GitHub Pages, без сервера, рекламы, магазина и аккаунтов.

## Запуск

Node.js 22.12+ (CI: Node.js 24).

```sh
npm ci
npm run dev
npm run check
npm run build
npm run preview
```

Адрес: `/sand-bucket/`. Dev-сервер подходит для локальной проверки; офлайн работает только в production на HTTPS или localhost. Публикация: https://lemonb.github.io/sand-bucket/ . Слияние PR требует отдельного одобрения владельца.

## Правила и интерфейс

- Квадратное поле песка 128×128 одинаково для всех сложностей. Квадрат занимает место, оставшееся после шапки, ленты, реального числа рядов вёдер и безопасных отступов iPhone. Игровой экран не прокручивается; на низком экране песок уменьшается, вся сетка вёдер остаётся видна. Размер canvas не влияет на размер контейнера.
- Волна из пяти уровней: знакомство, развитие, сочетание, испытание, передышка.
- Вёдра выходят через пустые клетки к верхнему краю, по вертикали/горизонтали. Стены неподвижны. Недоступные вёдра перевёрнуты; открывшиеся разворачиваются и увеличиваются.
- Выбор сразу резервирует первый свободный слот и освобождает клетку. Выход по кратчайшему пути длится 0,3 секунды при обеих скоростях, только затем начинается сбор. Одновременные выходы не сталкиваются.
- На конвейере пять углублений. Лента движется вправо, возвращаясь слева; оборот — 360 тактов. Ведро собирает свой цвет из пяти нижних рядов, включая песок за чужим цветом.
- Во время сбора цветные песчинки летят из нижних рядов к ведру; поток привязан к фактическим событиям сбора, пул ограничен 120 частицами.
- Полное ведро сразу освобождает слот; отдельный эффект завершает его подскок и исчезновение. Последний эффект заканчивается перед экраном победы.
- Победа — собран весь песок. Поражение определяется сразу после остановки песка и завершения отправок: когда нельзя добавить ведро и ни один цвет на ленте не совпадает с открытым песком в пяти нижних рядах. Ошибочные действия могут привести к поражению даже у решаемого уровня.
- Кнопка ×1/×2 ускоряет ленту и песок; остальные анимации всегда работают в темпе прежнего ×2. Скорость сохраняется между уровнями, перезапусками и открытиями приложения; первоначальное значение ×1.
- После уровня 400 кампания завершается. Пройденные уровни доступны для повтора без потери прогресса. Сохраняются номер, скорость и просмотренные подсказки; старые раскладки больше не используются. При повторе уровень и скрытые цвета остаются прежними.
- При уходе со страницы игра ставится на паузу. Reduced motion убирает декоративное движение, не меняя задержку выхода.

## Подготовка кампании

100 существующих рисунков повторяются четыре раза с интервалом 100 уровней. Семейства сетки: развилка, остров, обход, карманы. Браузер загружает компактный `src/levels/campaign.json`; генерация и поиск в клиенте отсутствуют. Пиксели восстанавливаются из каталога рисунков.

```sh
npm run campaign:pilot -- --workers=4
npm run campaign:generate -- --workers=4
npm run campaign:verify
```

Пилот проверяет 20 позиций из разных частей кампании. Полная команда заменяет каталог атомарно только после заполнения всех 400 позиций. Непроверенные кандидаты не подменяются запасными уровнями. Используются только локальный TypeScript и Node workers, без агентов, моделей, API и сети.

Кеш, доказательства, `report.json` и `gallery.html` находятся в `.cache/campaign/<fingerprint>/`. Fingerprint учитывает физику, рисунки и правила подготовки. Повторный запуск продолжает работу из кеша. Число workers: 1–8 (по умолчанию до 4). Результат не зависит от порядка завершения workers.

До 24 кандидатов на позицию. Сначала дешёвая политика, затем поиск с шириной 64, лимитом 5000 состояний и 100000 тактов симуляции. Исчерпание бюджета означает «не проверен». Решения проверяются настоящим `Game` по условиям собранного песка, завершённых вёдер и доступного цвета: обе скорости, паузы 0, 120, 1800 тактов и переменная пауза. Это не гарантирует победу при любом порядке ходов и любой задержке.

`campaign:verify` воспроизводит доказательства опубликованного каталога из кеша. После удаления кеша его восстанавливает полная генерация. Повторы структуры сравниваются с учётом механик и взаимного расположения цветов, включая горизонтальное отражение. Простая замена палитры не делает уровень новым. Отпечаток отбора отделён от отпечатка подготовки: изменение фильтра не требует заново считать физику уже проверенных кандидатов. Галерея и метрики помогают ручному просмотру: решаемость не доказывает интересность каждого уровня.

### Вместимость вёдер

Для одного игрового цвета максимальная вместимость не превышает минимальную больше чем в четыре раза. Учитываются вёдра на поле, внутри диспенсеров и на нижних слоях платформ. Умеренный разброс сохраняется; сумма вместимостей каждого цвета равна количеству его песка.

`npm run campaign:rebalance -- --workers=4` обрабатывает существующий каталог. Сначала меняются только вместимости, с сохранением пар смены цвета. Если допустимого распределения нет или штатный поиск не подтверждает решение, подбирается новая раскладка: до 24 кандидатов, с теми же рисунком, размером сетки, семейством и набором механик. Новый кандидат также обязан соблюдать предел 4:1 после балансировки.

Результаты сохраняются в `.cache/capacities/<fingerprint>/`: ключ учитывает исходный каталог, правила подготовки и проверки. Повторный запуск продолжает работу; `report.json` содержит диапазоны вместимостей до/после, сохранённые раскладки и причины неудач. Каталог заменяется атомарно только при успехе всех 400 позиций и проверке уникальности. Неполная партия не меняет каталог и не ослабляет правило. Подтверждаются обе скорости и четыре сценария пауз; готовые доказательства сохраняются для последующих проверок без повторной симуляции. Прогресс игрока сохраняется, новые данные используются со следующего запуска уровня.

### Выборочная проверка проходимости

```sh
npm run campaign:verify-playable -- --changed origin/main
npm run campaign:verify-playable -- --levels 6,209
npm run campaign:verify-playable -- --levels 6,209 --force
```

`--changed` сравнивает игровые данные с указанной Git-ревизией: раскладки, механики и итоговые цвета песка и вёдер. Изменение рисунка выбирает все уровни, использующие его. Изменение общих правил симуляции или проверяющего кода выбирает всю кампанию. Если в базовой ревизии ещё нет нового проверяющего кода, первый запуск также выбирает все уровни. `--levels` явно ограничивает выборку; без обоих параметров выбираются все 400 уровней. Структура каталога проверяется целиком без симуляции, даже при выборке.

Успешные результаты восьми сценариев сохраняются атомарно в `.cache/playable/verified/`. Ключ зависит от игровых данных и кода симуляции/проверки, а не от версии приложения, текстов подсказок, RGB-палитры или генератора. Совпавший результат позволяет пропустить симуляцию; старые доказательства сначала воспроизводятся. Повреждённая запись проверяется заново. `--force` пропускает кэш результатов, но может воспроизвести ранее найденное решение. Отчёт показывает `verified` (проверено симуляцией), `certificateHits` (готовые результаты) и выбранные номера. Выборочная проверка подтверждает только выбранные уровни.

Команда не изменяет уровни и не запускает генерацию. При отсутствии пригодного доказательства ищет решение существующей раскладки; ошибка блокирует выпуск затронутого изменения. Для проверки существующего каталога после очистки кэша используйте `campaign:verify-playable`, без регенерации. Тексты механик находятся отдельно в `src/mechanic-help.ts` и не сбрасывают кэш генерации.

Старые `generate:level` и `art-fallbacks.json` остаются для регрессионных проверок прежнего генератора; клиент их не использует.

## Производительность и проверки

- Пересчитываем только строки, затронутые перемещением, сбором или снятием крышки. Полностью неподвижный песок не пересчитывается, пока не появятся пустоты.
- Один буфер изображения песка, предвычисленные оттенки, обновление WebGL-текстуры только при изменении сетки.
- Геометрия ленты и вёдер переиспользуется; в кадре меняются позиции и заполнение. До 20 переиспользуемых эффектов. Проходы вычисляются после выбора ведра; DOM-счётчики обновляются только при изменении.
- Локальный синтетический замер 36 000 тактов неподвижного песка: около 2079 мс до изменения и 17 мс после. Новое поле содержит 128×128 клеток вместо прежних 128×112. Замер под параллельной тестовой нагрузкой; это не FPS и не оценка устройства.
- Обычный CI проверяет по 3 seed каждого класса прежнего генератора (12 всего), ручной полный прогон — по 100 (400 всего). Остальные тесты проверяют физику, механики, скрытые цвета, поиск и миграцию прогресса.
- Сборка проверяет доступность HTML и всех ресурсов через офлайн-кеш без сети.

Перед релизом на физическом iPhone проверить плавность при пяти вёдрах и ×2, нагрев, поля 6×6/7×7, управление пальцем, возврат после блокировки и офлайн-переходы. Desktop-проверка не подтверждает производительность телефона.

Полный прогон прежнего генератора запускается вручную: `npm run test:full` локально или Actions → Check and deploy → Run workflow на GitHub. Ручной запуск проверяет тесты и сборку, но не публикует сайт; публикация происходит после push в main. Каталог кампании полностью проверяется командой `campaign:verify`.

## Офлайн и обновления

После «Можно играть без интернета» приложение работает без сети, включая все уровни кампании. На iPhone: Safari → Поделиться → На экран «Домой». Обновления проверяются при запуске, возвращении в приложение, восстановлении сети и раз в минуту, пока игра видна. Новая сборка полностью скачивается в фоне: в меню применяется автоматически, во время попытки — при следующем переходе, повторе или выходе в меню. Выбранный уровень и действие сохраняются; прогресс и настройки не очищаются. Открытые вкладки сохраняют доступ к файлам своей сборки. Первый переход со старого механизма может потребовать одного повторного открытия после скачивания обновления. Очистка данных браузера удаляет прогресс и офлайн-кеш. При запрете localStorage можно играть, но прогресс хранится только в текущем открытии.

`/sand-bucket/interface.html` остаётся отдельным dev-макетом для сравнения согласованного интерфейса; в production не включается. В нём демонстрационное автоматическое заполнение, а не игровая симуляция.

Для проверки поражения в dev-сборке: `/sand-bucket/?scenario=loss`. Сценарий сам запускает пять неподходящих вёдер и показывает поражение через секунду после его определения. Кнопка повтора запускает его снова; сохранённый номер уровня не меняется. В production этот сценарий отключён.

## Картины и механики

В `src/art-catalog.ts` — 100 разных композиций: собственные геометрические мотивы и десять вариантов окружения. Первые три образца нарисованы отдельно. Это не 100 отдельных мотивов: объекты повторяются в разных сценах, но композиции не сводятся к смене палитры. Чужие изображения и игровые ассеты не использованы. Уровни 1–100 используют картины по порядку; далее цикл повторяется. Офлайн-каталог: `/sand-bucket/catalog.html` в dev-сборке.

Восемь механик вводятся по одной в пятиуровневых волнах, затем сочетаются. Каждый пятый уровень — передышка без специальных механик:

- Очередь: до пяти ведер; будущие цвета могут быть скрыты.
- Ключ: заполнение отмеченного ведра открывает проход.
- Платформа: цельный поднос с двумя слоями; нижний появляется после отправки всего верхнего. Его цвета показаны на краю или скрыты знаком ?.
- Поворотный поднос: 2×2, поворот по часовой стрелке после каждой успешной отправки.
- Мост: цельный настил; после отправки последнего ведра открывается нижний проход.
- Связанная пара: два свободных слота — отправляются оба ведра, если доступно нажатое. Один слот — отправляется нажатое, связь разрывается. Закрытый партнёр уходит вслед за доступным.
- Крышка: удерживает участок песка до заполнения отмеченного ведра.
- Смена цвета: пара вёдер равной вместимости с одинаковой меткой ⇄ обменивается цветами после каждого успешного хода. После отправки одного оба сохраняют текущие цвета. Сумма вместимостей каждого цвета остаётся равна количеству песка.

Специальные области не перекрываются. Во время выхода ведра и перестройки поля новые отправки временно заблокированы; лента продолжает движение. Пара считается одним ходом. При смене версии сохраняются номер уровня и ×1/×2, кеш старых раскладок сбрасывается.

Особые серые вёдра со знаком ? скрывают цвет до открытия пути и затем остаются раскрытыми. Вместимость и связи остаются видны. Скрытые слои очереди и платформы раскрываются при появлении. Повтор уровня сохраняет те же цвета.

Локальное сравнение генерации уровней 1, 8, 20, 24, 32 и 90: суммарно 15,6 с до оптимизации и 2,0 с после. Ускорение включает пропуск неподвижных строк и сокращение восьми поисков/воспроизведений до двух. На десяти уровнях старая и новая физика дали одинаковые клетки, события и заполнение вёдер на каждом такте при обеих скоростях. Это замер на компьютере, не оценка производительности iPhone.

Для dev-проверки отдельного уровня: `/sand-bucket/?level=3`. Этот режим не продвигает сохранённый номер уровня и отсутствует в production.

Специальные механики размещаются по всему полю; конкретная раскладка принимается только после проверки решения. Очереди, платформы, подносы, мосты, связи, замки, крышки и смена цвета имеют анимированные переходы. Системная настройка уменьшения движения отключает декоративные перемещения.

Все декоративные анимации работают с постоянной скоростью прежнего ×2. Кнопка ×1/×2 под лентой меняет скорость ленты и сбора/пересыпания песка. В главном меню показана версия из package.json. Уже показанные подсказки механик сохраняются вместе с прогрессом; кнопка ⓘ позволяет открыть их снова.

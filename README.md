# Sand Bucket

Личная браузерная игра с бесконечной последовательностью решаемых уровней. TypeScript, Vite и PixiJS; GitHub Pages, без сервера, рекламы, магазина и аккаунтов.

## Запуск

Node.js 22.12+ (CI: Node.js 24).

```sh
npm ci
npm run dev
npm run check
npm run build
npm run preview
```

Адрес: `/sand-bucket/`. Dev-сервер подходит для локальной проверки; офлайн работает только в production на HTTPS или localhost. Публикация: https://lemonb.github.io/sand-bucket/ . Слияние PR требует отдельного одобрения владельца.

## Правила и интерфейс

- Квадратное поле песка 128×128 одинаково для всех сложностей. На низком экране квадрат уменьшается, чтобы вся сетка вёдер оставалась видна. Размер canvas не влияет на размер контейнера.
- Волна: три простых уровня (4×4, без стен), три средних (5×5), два сложных (6×6), один очень сложный (7×7). Затем разгрузка — снова простые.
- Вёдра выходят через пустые клетки к верхнему краю, по вертикали/горизонтали. Стены неподвижны. Недоступные вёдра перевёрнуты; открывшиеся разворачиваются и увеличиваются.
- Выбор сразу резервирует первый свободный слот и освобождает клетку. Выход по кратчайшему пути длится 18 тактов (0,3 секунды при ×1), только затем начинается сбор. Одновременные выходы не сталкиваются.
- На конвейере пять углублений. Лента движется вправо, возвращаясь слева; оборот — 360 тактов. Ведро собирает свой цвет из пяти нижних рядов, включая песок за чужим цветом.
- Во время сбора цветные песчинки летят из нижних рядов к ведру; поток привязан к фактическим событиям сбора, пул ограничен 120 частицами.
- Полное ведро сразу освобождает слот; отдельный эффект завершает его подскок и исчезновение. Последний эффект заканчивается перед экраном победы.
- Победа — собран весь песок. Поражение — полный оборот без сбора/осыпания при невозможности добавить ведро. Ошибочные действия могут привести к поражению даже у решаемого уровня.
- Кнопка ×1/×2 ускоряет всю симуляцию. Скорость сохраняется между уровнями, перезапусками и открытиями приложения; первоначальное значение ×1.
- После победы — «Следующий». Сохраняются номер, seed, версия генератора и только текущая/следующая подготовленные раскладки. При закрытии незавершённая партия начинается заново. Старая отметка `sand-bucket.progress.v1` не удаляется, новая последовательность начинается с уровня 1.
- При уходе со страницы игра ставится на паузу. Reduced motion убирает декоративное движение, не меняя задержку выхода.

## Генерация

Рисунки: пейзажи, волны, кольца, ромбы и геометрические полосы с вариациями формы и палитры. Seed детерминирует весь уровень. Количество вёдер соответствует числу клеток без стен; сумма вместимостей каждого цвета точно равна его песку.

1. Выбрать картину по номеру уровня и разделить её песок на вместимости ведер.
2. Построить исходный порядок сбора без пространственных ограничений.
3. Разместить ведра и выбранные механики на поле.
4. Найти решение готового поля движком с настоящими правилами, задержками выхода и пятью слотами. Повторить поиск с задержками действий 6, 12 и 18 тактов.
5. Воспроизвести каждое найденное решение до победы. Только подтверждённые кандидаты допускаются в игру.

На каждый проход отводится максимум 30 000 тактов; на seed — до 24 кандидатов. Это подтверждает существование решения, а не победу при любом порядке действий.

Генерация выполняется в Web Worker. Пока идёт партия, готовится следующая. При ошибке, исчерпании попыток или превышении 15 секунд используется заранее проверенный запасной уровень нужной сложности. Запасной уровень использует ту же картину и размер поля, но без специальных механик; его раскладка сохраняется для повторных попыток. Непроверенные кандидаты не выдаются.

```sh
npm run generate:level
```

Команда вручную пересоздаёт 400 проверенных запасных уровней (100 картин × 4 размера) в `src/levels/art-fallbacks.json`. Пиксели не дублируются в JSON, они восстанавливаются из каталога. При изменении правил генерации увеличивать `GENERATOR_VERSION` и обновлять запасные уровни вместе с проверками.

## Производительность и проверки

- Не пересчитываем осыпание полностью неподвижного песка, пока сбор снова не создаст пустоты.
- Один буфер изображения песка, предвычисленные оттенки, обновление WebGL-текстуры только при изменении сетки.
- Геометрия ленты и вёдер переиспользуется; в кадре меняются позиции и заполнение. До 20 переиспользуемых эффектов. Проходы вычисляются после выбора ведра; DOM-счётчики обновляются только при изменении.
- Локальный синтетический замер 36 000 тактов неподвижного песка: около 2079 мс до изменения и 17 мс после. Новое поле содержит 128×128 клеток вместо прежних 128×112. Замер под параллельной тестовой нагрузкой; это не FPS и не оценка устройства.
- Обычный CI проверяет по 3 seed каждого класса (12 всего), ручной полный прогон — по 100 (400 всего). Остальные тесты всегда выполняются: точное воспроизведение, задержки, стены/пути, сбор, сохранение песка, ×1/×2, сохранение скорости/уровней, кеширование, ошибки и тайм-аут Worker.
- Сборка проверяет доступность HTML, Worker и всех ресурсов через офлайн-кеш без сети.

Перед релизом на физическом iPhone проверить плавность при пяти вёдрах и ×2, нагрев, поля 6×6/7×7, управление пальцем, возврат после блокировки и офлайн-переходы. Desktop-проверка не подтверждает производительность телефона.

Полный прогон запускается вручную: `npm run test:full` локально или Actions → Check and deploy → Run workflow на GitHub. Ручной запуск проверяет тесты и сборку, но не публикует сайт; публикация происходит после push в main. Проверка каждого генерируемого уровня внутри игры остаётся обязательной.

## Офлайн и обновления

После «Можно играть без интернета» приложение работает без сети, включая генерацию следующих уровней. На iPhone: Safari → Поделиться → На экран «Домой». Обновление применяется после закрытия всех окон игры и повторного открытия. Очистка данных браузера удаляет прогресс и офлайн-кеш. При запрете localStorage можно играть, но прогресс хранится только в текущем открытии.

`/sand-bucket/interface.html` остаётся отдельным dev-макетом для сравнения согласованного интерфейса; в production не включается. В нём демонстрационное автоматическое заполнение, а не игровая симуляция.

Для проверки поражения в dev-сборке: `/sand-bucket/?scenario=loss`. Сценарий сам запускает пять неподходящих вёдер и заканчивается поражением после одного оборота. Кнопка повтора запускает его снова; сохранённый номер уровня не меняется. В production этот сценарий отключён.

## Картины и механики (генератор v3)

В `src/art-catalog.ts` — 100 разных композиций: собственные геометрические мотивы и десять вариантов окружения. Первые три образца нарисованы отдельно. Это не 100 отдельных мотивов: объекты повторяются в разных сценах, но композиции не сводятся к смене палитры. Чужие изображения и игровые ассеты не использованы. Уровни 1–100 используют картины по порядку; далее цикл повторяется. Офлайн-каталог: `/sand-bucket/catalog.html` в dev-сборке.

Первые восемь уровней показывают механики по одной, затем чередуются обычные уровни, одна механика и проверенные сочетания двух:

- Очередь: до пяти ведер с видимыми следующими цветами.
- Ключ: заполнение отмеченного ведра открывает проход.
- Платформа: цельный поднос с двумя слоями; нижний появляется после отправки всего верхнего. Его цвета видны на краю.
- Поворотный поднос: 2×2, поворот по часовой стрелке после каждой успешной отправки.
- Мост: цельный настил; после отправки последнего ведра открывается нижний проход.
- Связанная пара: два свободных слота — отправляются оба доступных ведра одним ходом. Один слот — отправляется нажатое, связь разрывается. Если слотов два, а проход партнёра закрыт, пара ждёт.
- Крышка: удерживает участок песка до заполнения отмеченного ведра.
- Смена цвета: оставшееся на поле ведро чередует два цвета после каждого успешного хода. Отправленное сохраняет цвет. Неверный момент выбора может привести к проигрышу.

Специальные области не перекрываются. Во время выхода ведра и перестройки поля новые отправки временно заблокированы; лента продолжает движение. Пара считается одним ходом. При смене версии сохраняются номер уровня и ×1/×2, кеш старых раскладок сбрасывается.

Генератор ищет решение текущего состояния, учитывая доступные проходы, удерживаемый песок и смену цветов, затем воспроизводит его. Дополнительно ищет и воспроизводит решения с задержками действий 6, 12 и 18 тактов: последующие решения могут отличаться, если задержка изменила доступные ходы. Полный перебор всех действий игрока не выполняется. Быстрый CI также проверяет восемь отдельных механик и восемь сочетаний; полный seed-прогон остаётся ручным.

Для dev-проверки отдельного уровня: `/sand-bucket/?level=3`. Этот режим не продвигает сохранённый номер уровня и отсутствует в production.
